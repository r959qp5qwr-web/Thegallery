# 04 — Consistency and duplication (reviewer 4 of 5)

Lens: one product, one grammar? Method: `ui-consistency:finding-patterns` (pattern checklist derived from
`src/components/Chrome.tsx`, the 27 page files, `public/gallery/system.css`, `app.css`, `tokens.css`, and the
captures), then `ui-consistency:verifying` (every page walked against it). All captures cited are under
`/tmp/claude-0/-workspace/75f6409c-b829-5874-b75e-f444b1240fa6/scratchpad/captures/`.

## Verdict

The governor's "duplication" is literal and measurable. Pages are not built from one page template. Each
page assembles its own top of page from five overlapping parts: a header place, a context line, a hidden h1,
a visible heading at h1 or h2, and an eyebrow. The pages also use the same few words in all five. The worst
case is For Makers at 1440, which says "For Makers" four times on one screen and "One gallery of your own"
twice. The work page names the maker four times above the footer. Every public page shows the four
sections twice on a phone, once in the bottom bar and once in the footer. There is no template, so
everything else drifts as well:

- The header has **five** shapes, and the wordmark is missing on every back-arrow page.
- The same "Back to the entrance" exit uses **three** button styles on three pages.
- Empty and unavailable states use **three** different components.
- The space above the first heading takes **five** values: 48, 32, 72, 30 and 8 px.
- The side margin switches from 20 px to 16 px partway through the maker's sign-up.
- The page code carries **82 inline `style={{}}`** objects in 26 files, overriding the system with values
  like 6, 10, 14 and 28 px that are off the system's own rhythm.

None of this is a token problem. It comes from having no page template and no rule for "say each thing
once". Fix those two and most rows below close together.

- [ ] notice: `Band` (shared). Consistent, except `ActionForm`/`PublishButton` hand-write `.band` with an
  inline margin.
- [ ] footer: `Chrome.Footer`, 4 links, one of which (`/makers`) duplicates a section.
- [ ] spacing: through tokens `--s1…--s7` (4 px base, rhythm 8·16·24·32·48). Off-base literals are in

- [ ] side padding: `--pad-x` 20 (public) / `--pad-x-studio` 16 (Studio) below 600 px, per foundation §4.
  The For Makers → Create account flow crosses that line.
- [ ] not to be copied from any page: inline `font:` on headings, `style={{padding:0}}` to cancel a class's
  own padding, a hand-written `.band`.

## Moves (lift the whole product)

1. **One page template, `<Page>` in Chrome.tsx**: header → optional eyebrow → one visible h1 → body →
   footer. Pages pass data, not structure. This kills C-03, C-05, C-08, C-09, C-13 and most of C-14 in one
   change, and makes "the same component looks different on different pages" structurally impossible.
2. **A "say it once" rule, written into INTERFACE_FOUNDATION §8 and enforced by review.** On any screen a
   place name, a person's name or a state is stated by exactly one element. The nav item is the place;
   the h1 is the page; the empty state is the emptiness. Headers do not repeat h1s; context lines do not
   repeat empty states; footers do not repeat sections.
3. **One header, with the wordmark everywhere.** Back is not a header role on a public site with persistent
   navigation. The gallery's name on every screen, including the shared work link, is the cheapest
   brand dignity available.
4. **Zero inline styles.** Move the 82 to named classes in app.css and add a lint rule. Each one was a
   moment where a page quietly forked the system.
5. **Collapse to the foundation's components:** one empty state (`EmptyPlinth`), one wall label
   (`WallLabel`), one primary action (`Action primary`). Exits are text links. Mono for labels, never for
   sentences.
